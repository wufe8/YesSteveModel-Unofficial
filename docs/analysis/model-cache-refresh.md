# 模型更新与运行中清理缓存

模型源文件、服务端同步索引、客户端磁盘缓存和已注册的运行时资源是不同层。删除缓存文件不是重新扫描模型源，也不是取消已经进行的同步或解析。

## 操作语义

下表以默认统一同步协议为准。

| 操作 | 应得到的结果 | 边界 |
| --- | --- | --- |
| 修改服务端 `config/ysmu/custom` 后执行 `/ysm reload` | 重新扫描新增、修改和删除的模型，重建必要缓存，通知所有维度的在线玩家重新握手 | 等源文件保存完成后再重载；扫描期间仍修改文件的模型不会被登记为成功缓存，稳定后再次重载 |
| `/ysm sync` | 发起者重新握手，清理旧注册状态，再获取当前服务端索引 | 不重新扫描服务端源文件，不等于管理员执行 `/ysm reload` |
| 删除服务端模型缓存后执行 `/ysm reload` | 从仍然存在的源模型重建缺失缓存 | 内容和序列化配置没变时，客户端继续使用相同内容的旧缓存是正确行为 |
| 只删除服务端缓存后执行 `/ysm sync` | 不保证成功 | 当前服务端内存索引可能仍指向已删除的文件，缺失会报告同步失败；应先由管理员执行 `/ysm reload` |
| 删除客户端缓存后执行 `/ysm sync` | 重新下载当前服务端索引里的缺失文件 | 客户端删除文件不更新服务端源模型列表 |
| 删除客户端缓存而不重新同步 | 已加载的资源可能暂时显示 | 懒加载或闲置释放后的资源需要再次读取缓存；没有自动下载或文件监视机制 |
| 同步期间删除缓存文件 | 不保证得到最新源模型 | 已读入内存的任务仍可能完成，下载任务也会重新创建文件；先稳定源文件，再执行完整重载或重新同步 |
| `/ysmclient load` | 添加启动扫描时已发现、但尚未注册的本地模型 | 尚不提供运行中的本地增删改刷新；修改本地源文件后可靠的刷新方式是重启客户端 |

`config/ysmu/builtin` 是自动提取目录。内置模型重载会覆盖它；用户模型应放在 `custom`。

## 缓存身份与发布顺序

服务端索引缓存的有效性和同步模型哈希必须同时考虑序列化配置，例如是否包含模型音效。只让服务端重建、却继续发送相同的模型哈希，不能使已经缓存旧数据的客户端重新下载。缓存格式实现发生变化时也需要更新序列化修订号。

客户端每轮重载使用独立的应用代次。任务从开始到发布应始终携带原代次，不能在较晚的解析阶段重新采样。新握手需等待主线程完成旧资源清理；模型注册与其懒加载缓存路径应在同一次受检的主线程发布中完成。

## 尚未提供的恢复能力

- `/ysmclient load` 的本地源重新扫描、按来源撤销与替换需要独立实现；直接调用集成服的全局重载会影响该存档里的其他玩家，直接清空客户端注册表也会清掉服务端模型。
- 运行中任意删除整个缓存目录后的自动恢复，需要缺失文件触发重建或重新下载，以及同步失败的明确反馈。当前不要将手动删除文件当作在线更新入口。
- 老同步分块文件的删除与累计状态、后台音效预暖的跨代次发布仍需进一步补齐生命周期验证。
